Bu sənəd, bazanın ilk anından (boş `CREATE DATABASE`) indiki vəziyyətinə (13 sxema, 61 cədvəl, trigger-lər, hesabat view-ları, real doldurulmuş data) qədər olan hər addımı, birbaşa köçürülüb işlədilə bilən SQL kodları ilə sənədləşdirir. Fəlakət anında (bazanın yenidən sıfırlanması kimi) bu sənəd tək başına bazanı tam bərpa etmək üçün kifayətdir.

00 Bu dərs nə üçündür

Bu, əvvəlki bir mərhələdə (PostgreSQL-in yenidən başlanğıc vəziyyətinə düşməsi nəticəsində) real datanın itirilməsindən sonra yazılan bir "sığorta sənədidir". Məqsəd: bir daha oxşar hadisə baş versə, heç bir söhbət tarixçəsinə ehtiyac olmadan, bu tək HTML faylındakı SQL kodlarını ardıcıl işlədərək bazanı tam bərpa edə bilməkdir.

Şəffaflıq üçün vacib qeyd: Bu dərs bazanın strukturunu (sxema, cədvəl, trigger, view) 100% dəqiqliklə bərpa edir. Amma real sətir məlumatını (məsələn konkret işçi adları, konkret anbar qalıqları) bu fayl daxilində saxlamır — çünki bu, ya çox böyük olardı, ya da davamlı dəyişən canlı datadır. Bölmə 18 və 19-da bunun necə idarə olunacağı izah edilir.

16 Trigger-lər — updated_at avtomatik yenilənməsi

Real ERP-lərdə bir qayda var: bir sətir dəyişəndə, updated_at sütunu əl ilə yox, sistem tərəfindən avtomatik yenilənməlidir. Bunun üçün bir funksiya yazırıq, sonra onu updated_at sütunu olan HƏR cədvələ "bağlayırıq" — əl ilə 40+ dəfə etmək əvəzinə, bir kod bloku ilə avtomatik edirik.

sql — 1. Ortaq funksiya
CREATE OR REPLACE FUNCTION set_updated_at()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = NOW();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;
sql — 2. Bu funksiyanı bütün uyğun cədvəllərə avtomatik bağla
DO $$
DECLARE
  r RECORD;
BEGIN
  FOR r IN
    SELECT table_schema, table_name
    FROM information_schema.columns
    WHERE column_name = 'updated_at'
      AND table_schema IN ('asset','finance','hr','inventory','logistics',
                            'org','partner','production','purchase',
                            'quality','sales','system','trade')
  LOOP
    EXECUTE format(
      'DROP TRIGGER IF EXISTS trg_set_updated_at ON %I.%I;
       CREATE TRIGGER trg_set_updated_at
       BEFORE UPDATE ON %I.%I
       FOR EACH ROW EXECUTE FUNCTION set_updated_at();',
      r.table_schema, r.table_name, r.table_schema, r.table_name
    );
  END LOOP;
END $$;
Necə işləyir: Bu blok information_schema.columns-a baxıb, updated_at sütunu olan BÜTÜN cədvəlləri özü tapır (əl ilə siyahı yazmağa ehtiyac yoxdur) və hər birinə trigger bağlayır. Gələcəkdə yeni cədvəl əlavə etsəniz və onda da updated_at olsa, bu blok yenidən işlədilməklə o da avtomatik daxil olacaq.

17 Hesabat View-ları

View-lar — tez-tez lazım olan mürəkkəb sorğuları "əvvəlcədən hazırlanmış cədvəl" kimi saxlayan qısayollardır. Bunlar Shiny/AI tətbiqinin (app.R) artıq işlətdiyi sorğu məntiqini əsas götürür.

17.1 — hr.v_department_headcount

sql
CREATE OR REPLACE VIEW hr.v_department_headcount AS
SELECT d.dept_name, COUNT(e.id) AS employee_count,
       ROUND(AVG(e.monthly_salary),2) AS avg_salary,
       SUM(e.monthly_salary) AS total_monthly_cost
FROM hr.employees e
JOIN hr.departments d ON e.department_id = d.id
WHERE e.is_active
GROUP BY d.dept_name;

17.2 — finance.v_monthly_pl

sql
CREATE OR REPLACE VIEW finance.v_monthly_pl AS
SELECT TO_CHAR(DATE_TRUNC('month', gl.transaction_date), 'YYYY-MM') AS month,
       SUM(CASE WHEN coa.account_type = 'revenue' THEN gl.credit - gl.debit ELSE 0 END) AS income,
       SUM(CASE WHEN coa.account_type = 'expense' THEN gl.debit - gl.credit ELSE 0 END) AS expense
FROM finance.general_ledger gl
JOIN finance.chart_of_accounts coa ON gl.account_id = coa.id
GROUP BY month ORDER BY month;

17.3 — inventory.v_stock_valuation

sql
CREATE OR REPLACE VIEW inventory.v_stock_valuation AS
SELECT c.category_name,
       SUM(i.quantity_on_hand * COALESCE(i.last_selling_price, p.selling_price_local, p.standard_cost, 0)) AS total_value,
       SUM(i.quantity_on_hand) AS total_qty
FROM inventory.inventory i
JOIN inventory.products p ON i.product_id = p.id
LEFT JOIN inventory.categories c ON p.category_id = c.id
GROUP BY c.category_name;

17.4 — inventory.v_low_stock

sql
CREATE OR REPLACE VIEW inventory.v_low_stock AS
SELECT p.product_code, p.product_name,
       SUM(i.quantity_on_hand) AS quantity, p.reorder_point
FROM inventory.inventory i
JOIN inventory.products p ON i.product_id = p.id
GROUP BY p.product_code, p.product_name, p.reorder_point
HAVING SUM(i.quantity_on_hand) < p.reorder_point;

17.8 — purchase.v_supplier_performance

sql
CREATE OR REPLACE VIEW purchase.v_supplier_performance AS
SELECT s.company_name, s.rating,
       COUNT(DISTINCT o.id) AS total_orders,
       SUM(o.total_amount) AS total_purchased,
       ROUND(100.0 * SUM(ol.received_qty) / NULLIF(SUM(ol.ordered_qty),0), 1) AS fulfillment_pct
FROM purchase.suppliers s
LEFT JOIN purchase.orders o ON o.supplier_id = s.id
LEFT JOIN purchase.order_lines ol ON ol.po_id = o.id
GROUP BY s.company_name, s.rating;
Nə üçün view, cədvəl deyil? View "canlı" sorğudur — arxasındakı cədvəllər dəyişən kimi (yeni işçi, yeni faktura), view-un nəticəsi də avtomatik yenilənir. Ayrıca "sinxronizasiya" lazım deyil.
